# When Gibbs Damping Is Absorbed: Training Priors in Free-Coefficient Polynomial GNNs — code and results

Code and result files accompanying the LoG 2026 paper *When Gibbs Damping Is Absorbed: Training Priors
in Free-Coefficient Polynomial GNNs*. This repository lets a reader re-run
the experiments in the paper, regenerate the figures from cached results, and trace each reported
number to the script and versioned result file that produced it. `results/README.md` records, per
file, whether the shipped entry point regenerates it in full.

Self-contained: every empirical number, table, and figure traces to a versioned file under `results/`,
and each traces to the script listed in the manifest below (`results/README.md` records the exact
provenance of each file). Section 3 (the ringing-law constants) is analytic and closed-form (e.g. the
Gibbs constant is `(1/pi)*Si(pi) - 1/2 ~= 0.0894899`), verifiable directly from the paper; its computed
values are in `results/theory_step1_gibbs_overshoot_v001.json`.

A quick integrity check (loads the cached results, verifies headline values, regenerates the figures):
```bash
python src/check_results.py
```

## Setup
```bash
pip install -r requirements.txt      # Python 3.10+
```
Datasets download automatically via PyTorch Geometric on first run (Planetoid, WebKB/WikipediaNetwork,
WikiCS, HeterophilousGraphDataset); small eigendecompositions/graphs cache to `data/cache/` (created on
first run). No dataset files are shipped.

## Reproduce the figures (fast; from cached results)
```bash
python src/paper_figures.py          # regenerates every figure PDF/PNG from results/*.json
bash   src/make_type1.sh             # converts figure text to outlines (LoG requires Type-1 only)
```
The `results/*.json` files are the exact per-run outputs behind every reported number, so the tables and
figures reproduce without re-running the experiments.

## Re-run the experiments
Reproduction of ChebGibbsNet (official impl. `github.com/hazdzz/chebgibbsnet`, paper-era commit
`bb3235c`), K=10 throughout, Adam.

The manuscript-level cached result files -- the `*_seeds` / `*_paired` / `factorial_splits` JSONs behind
the figure error bars and table CIs -- are regenerated by `stats_variance.py`:
```bash
python src/repro/stats_variance.py --stages lowpass    # -> results/lowpass_seeds_v001.json     (Fig. 1)
python src/repro/stats_variance.py --stages data       # -> results/data_regime_seeds_v001.json (Fig. 2)
python src/repro/stats_variance.py --stages factorial  # -> results/factorial_splits_v001.json  (Tables 4 & 7)
python src/repro/stats_variance.py --stages platonov   # -> results/platonov_paired_v001.json   (Table 3)
python src/repro/stats_variance.py --smoke             # ~2-4 min end-to-end sanity check (writes *_smoke.json)
python src/repro/stats_variance.py                     # all four stages, full variance (hours)
```
The standalone repro scripts below are shorter single-configuration diagnostic runs. They may write
auxiliary JSON files (e.g. `lowpass_vs_kpm_v001.json`, `platonov_breadth_v001.json`, `gso_ablation_v001.json`)
that are NOT the manuscript cached files above -- use them to inspect one configuration, not to regenerate
the figures/tables:
```bash
python src/repro/lowpass_vs_kpm.py          # low-pass vs KPM taper comparison (deployed model)
python src/repro/platonov_breadth.py        # clean Platonov heterophily suite
python src/repro/gso_ablation.py            # 2x2x2 factorial {damping x sign x activation}
```

The Appendix D experiments are standalone and each writes its own cached file:
```bash
python src/repro/rebuttal_planted_band.py   # -> results/rebuttal_planted_band_v002.json  (App. D.1)
python src/repro/rebuttal_breadth.py        # -> results/rebuttal_breadth_v002.json       (App. D.2)
python src/repro/rebuttal_stability.py      # -> results/rebuttal_stability_v001.json     (App. D.3)
python src/repro/rebuttal_stats.py          # -> results/rebuttal_stats_v001.json         (derived CIs)
```
`rebuttal_stats.py` reads the three files above and is the single source of the bootstrap intervals
quoted in D.2 and D.3, so the paper and any re-derivation cannot drift apart.
Runtime/memory: a single RTX-class GPU is assumed. The Planetoid runs build dense normalized operators;
PubMed (n=19717) needs a few GB of RAM/VRAM. The citation/factorial/Platonov re-runs are minutes to tens
of minutes; the full variance re-run is hours. All figures/tables reproduce instantly from the cached
`results/*.json` without any re-run.
